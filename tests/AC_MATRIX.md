# Acceptance-criteria matrix

Every acceptance criterion in `docs/product-specification.md` §9, the test layer(s) that verify it, and where it stands. A change touching an AC updates its row and its test (AGENTS.md).

Layers (architecture §9): **U** domain unit · **I** API integration (real local Postgres) · **S** ElevenLabs simulation/agent test on the staging agent (`backend/agent/tests/*.json`, synced by `push.py`) · **P** Playwright · **L** live call script (#37).

Status, per layer (ticket #36, the basis of the final report):
- **done**: the test exists in the repo and passed in the last full run (backend `pytest`, frontend Vitest and Playwright, all against local Postgres; providers faked where noted).
- **written-not-run**: the test exists in the repo but has never run. This is every S test: it needs the ElevenLabs staging agent (`uv run python -m agent.push --env staging`, then run the agent tests).
- **deferred**: not runnable in this repo without accounts or a decision; no test written. L (live staging calls, real SMS/email, #37) needs ElevenLabs, Twilio, Postmark and staging. A deferred part that is a product gap rather than an account gap is listed under Exceptions below.

Suite-wide S conditions (#36): every simulation in `backend/agent/tests/` (46) ends with the same three conditions, ACX.1, ACX.2 and AC6.4, word for word. `tests/unit/test_agent_guards.py::test_every_simulation_judges_acx_1_acx_2_and_ac6_4` fails if one is missing. `tests/unit/test_ac_matrix.py` fails if a spec AC has no row, a status uses another word, a cited test or file does not exist, or an EL test is not cited.
